# Project File Map

## Purpose

This document is a navigation aid for humans, Codex sessions, and future AI planning chats. It explains what the main files and folders are for, how the Python prototype and browser app relate to each other, and which files are generated or intentionally tracked.

Update this file when files are added, removed, renamed, or significantly repurposed.

## Top-Level Repo Structure

- `README.md`: Project entry point with current status, setup commands, important paths, and development notes.
- `requirements.txt`: Python dependency list for the preserved prototype.
- `settings.py`: Python prototype constants, map settings, colors, and terrain thresholds.
- `generator.py`: Python map generation reference logic.
- `world.py`: Python world/tile data container and JSON export path.
- `map.py`: Python/Pygame map renderer and export trigger.
- `tile.py`: Python tile geometry and sprite wrapper.
- `main.py`: Python/Pygame prototype entry point.
- `docs/`: Project design, roadmap, and focused planning docs.
- `web/`: Browser app built with Vite, TypeScript, and HTML Canvas.
- `exports/`: Generated Python JSON export output. Ignored by Git.
- `full_map.png`: Generated Python preview image. Ignored by Git.
- `tiles/`: Preserved legacy tile asset folder. The current prototype draws solid-color hexes, but these assets are still present.

## Python Prototype

The root Python files are the preserved prototype and reference implementation. They should stay runnable while browser work continues.

- `main.py`: Starts the Python/Pygame prototype.
- `settings.py`: Holds Python constants, dimensions, colors, terrain thresholds, and related settings.
- `generator.py`: Contains the Python world generation reference.
- `world.py`: Defines the Python map/tile data model path and JSON export behavior.
- `map.py`: Handles Python/Pygame map rendering and triggers local preview/export behavior.
- `tile.py`: Handles tile geometry and sprite-style wrapping for the Python renderer.
- `requirements.txt`: Lists Python dependencies needed to run the prototype.

Expected local outputs from the Python path:

- `full_map.png`
- `exports/map_data.json`

These outputs are generated locally and should not be committed.

## Browser App

The browser app in `web/` is the release target. It uses Vite, TypeScript, and HTML Canvas. It can load sample JSON and generate maps in the browser.

- `web/package.json`: Browser app scripts and npm dependency metadata.
- `web/package-lock.json`: Locked npm dependency versions for reproducible installs.
- `web/index.html`: HTML entry point for the Vite app.
- `web/public/sample-map.json`: Tracked sample map used by the browser sample-load flow.
- `web/src/main.ts`: Browser app orchestration and UI wiring.
- `web/src/browserGenerator.ts`: TypeScript browser-side map generator.
- `web/src/seededRandom.ts`: Seeded random helpers used by browser generation.
- `web/src/renderCanvas.ts`: Canvas renderer for hex-map display.
- `web/src/loadMapJson.ts`: JSON loading/parsing support for map data.
- `web/src/downloads.ts`: Browser download helpers for JSON and PNG export.
- `web/src/mapTypes.ts`: Shared TypeScript map-data types.
- `web/src/sampleMap.ts`: Sample-map loading bridge for the browser app.
- `web/src/style.css`: Browser app styling.

Planned future browser diagnostics files:

- `web/src/mapDiagnostics.ts`: Planned diagnostics calculator for map metrics and export-ready review data. Not yet implemented.
- `web/src/mapReviewTypes.ts`: Planned TypeScript types for Map Lab review labels, ratings, flags, notes, exports, and sessions. Not yet implemented.

Other web assets may exist under `web/public/` and `web/src/assets/`. Inspect them before editing; do not assume they are unused.

## Generated And Ignored Files

- `full_map.png` is generated by the Python prototype and ignored.
- `exports/map_data.json` is generated by the Python prototype and ignored.
- `web/node_modules/` is local npm dependency output and ignored.
- `web/dist/` is generated by the browser build and ignored.
- `web/public/sample-map.json` is intentionally tracked as the browser sample map.

Do not edit or commit generated outputs as part of normal feature work.

## Development Flow

- The Python prototype remains preserved as a runnable reference.
- The browser app is the release target.
- Feature work should usually happen in small branches from `prep/browser-mapgen-foundation` until `main` is updated with the browser-mapgen foundation.
- Documentation should be updated after meaningful structure, status, setup, or design changes.

Before editing code, read `README.md`, `docs/design.md`, `docs/roadmap.md`, and any focused spec relevant to the work.
